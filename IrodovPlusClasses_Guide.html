3. Deep Dive: Backend Codebase Explained for Beginners

A. Server Entry Point (Backend/index.js)

This is the heart of the backend server. It boots up Express, connects to MongoDB, attaches middleware, and exposes routes.

const express = require('express');
const app = express();
const cookieParser = require('cookie-parser');
const cors = require('cors');

// 1. CORS Configuration
const allowedOrigins = [
  'https://irodovplusclasses.in',
  'http://localhost:5173',
  'http://localhost:3000',
  'http://127.0.0.1:5173'
];
app.use(cors({
  origin: function (origin, callback) {
    if (!origin) return callback(null, true);
    if (allowedOrigins.indexOf(origin) !== -1 || process.env.NODE_ENV !== 'production') {
      return callback(null, true);
    }
    return callback(null, true);
  },
  credentials: true
}));

// 2. Body Parsing Middleware
app.use(express.json()); // Parses incoming application/json requests
app.use(express.urlencoded({ extended: true })); // Parses URL-encoded form submissions
app.use(cookieParser()); // Parses cookies from request headers into req.cookies

// 3. Mounting REST Routers
app.use('/owners', ownerRouter);
app.use('/api/enroll', enrollRoutes);
app.use('/api/students', studentRouter);
app.use('/api/resources', resourceRouter);

// 4. Server Listener
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});
Key Learning Point: Why credentials: true in CORS? Because when the frontend stores or sends HTTP-only authentication cookies across different origins (e.g., port 5173 to port 3000), browsers block cookies unless both the client (Axios withCredentials: true) and server (CORS credentials: true) explicitly allow them.

E. Resource & PDF Streaming Router (Backend/Route/resourceRouter.js)

Handles Multer memory-storage uploads, database projection optimization, and HTTP stream headers.

// 1. Memory Storage Upload (Max 30MB, PDF only)
const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 30 * 1024 * 1024 },
  fileFilter: (req, file, cb) => {
    if (file.mimetype === 'application/pdf' || file.originalname.endsWith('.pdf')) {
      cb(null, true);
    } else {
      cb(new Error('Only PDF files are allowed!'), false);
    }
  }
});

// 2. Listing Query with Field Projection (.select('-pdf.data'))
router.get('/', async (req, res) => {
  const { subject, classGrade, search } = req.query;
  const query = {};
  if (subject && subject !== 'All') query.subject = subject;
  if (classGrade && classGrade !== 'All') query.classGrade = classGrade;

  // Crucial: Exclude pdf.data buffer to make response ultra-fast!
  const resources = await Resource.find(query).select('-pdf.data').sort({ createdAt: -1 });
  res.json({ success: true, resources });
});

// 3. Inline View vs Download Streaming
router.get('/:id/view', async (req, res) => {
  const resource = await Resource.findById(req.params.id);
  res.setHeader('Content-Type', 'application/pdf');
  res.setHeader('Content-Disposition', `inline; filename="${resource.pdf.fileName}"`);
  res.send(resource.pdf.data);
});

useEffect(() => {
  const loadStudent = () => {
    const saved = localStorage.getItem('studentUser');
    setStudent(saved ? JSON.parse(saved) : null);
  };
  loadStudent(); // Load on initial mount
  
  // Custom Window Event listener!
  window.addEventListener('studentAuthChange', loadStudent);
  return () => window.removeEventListener('studentAuthChange', loadStudent);
}, []);

const handleLogout = () => {
  localStorage.removeItem('studentUser');
  localStorage.removeItem('studentToken');
  setStudent(null);
  window.dispatchEvent(new Event('studentAuthChange')); // Dispatches event across app
};

5. Top Interview Questions & Detailed Technical Answers

Q1: Walk me through the architecture of your project and the lifecycle of a request.

Answer: Our platform follows a 3-tier MERN client-server architecture:

  1. Presentation Layer: React 19 SPA running in the browser, routing handled client-side by React Router DOM.
  2. Application / API Gateway Layer: Node.js with Express 5 REST API handling route endpoints, CORS headers, cookie decoding, and Multer file parsing.
  3. Data Layer: MongoDB Atlas managed document database, mapped through Mongoose 8 schemas.

Request Lifecycle Example: When a student logs in:

  • React Hook Form validates the email format and minimum password length client-side.
  • Axios makes an asynchronous POST /api/students/login request.
  • Express passes the request through CORS and express.json() middlewares.
  • studentRouter.js queries MongoDB via Student.findOne({ email }).
  • Bcrypt compares the plain password against the stored 60-character bcrypt hash.
  • If valid, a signed JWT token is issued, and returned alongside student metadata.
  • The React client saves the token in localStorage, fires an auth update event, and re-renders the navbar.
Q2: Why did you choose Bcrypt over SHA-256 for password security?

Answer:

  • SHA-256 is designed to be fast: It is designed for file hashing and cryptographic proof. Because it is fast, modern GPUs can calculate billions of SHA-256 hashes per second, making offline rainbow table and brute-force attacks trivial.
  • Bcrypt is deliberately slow and adaptive: It is an adaptive key derivation function based on the Blowfish cipher. It includes a built-in salt to defeat rainbow tables and a configurable work factor (salt rounds = 10, meaning 210 iterations). This makes computing guesses computationally expensive, protecting user passwords against brute force even if the database is leaked.
Q3: How do you handle file uploads, and why store buffers in MongoDB instead of AWS S3?

Answer:

  • Mechanism: We use multer.memoryStorage(). Instead of writing files to the web server's transient disk (which fails on serverless platforms like Render/Heroku where dyno filesystems are ephemeral), Multer holds the file in memory as a binary Buffer. We then persist { data: req.file.buffer, contentType: req.file.mimetype } into MongoDB.
  • Trade-off Discussion:
    • Advantage for this project: Self-contained architecture without needing third-party AWS S3 credentials or payment setup; atomic database operations (deleting a resource document automatically purges its file).
    • Production Trade-off: MongoDB documents have a 16MB BSON size limit. In high-traffic enterprise architectures, we would upload to an AWS S3 bucket or Cloudinary CDN and store only the secure S3 URL in MongoDB to conserve database RAM.
Q4: How did you optimize database queries when listing resources with large PDF files?

Answer: By default, Mongoose returns the full document including the binary pdf.data buffer. If an admin uploads 20 notes of 5MB each, querying Resource.find() would attempt to pull 100MB of binary data over the network on every page load!

To eliminate this bottleneck, we used Mongoose Field Projection:

const resources = await Resource.find(query)
  .select('-pdf.data') // Explicitly excludes the heavy binary buffer
  .sort({ createdAt: -1 });

This reduces the payload from 100MB down to ~2KB of lightweight JSON metadata (title, subject, size, upload date). The binary data is only loaded when a student specifically clicks on that individual file's view or download route.

Q5: How did you implement PDF viewing inline in the browser versus forcing a download?

Answer: This is controlled by the HTTP Content-Disposition response header:

  • Inline Preview: res.setHeader('Content-Disposition', 'inline; filename="notes.pdf"');
    Tells the browser's built-in PDF reader to open and display the PDF directly in the browser tab.
  • Forced Download: res.setHeader('Content-Disposition', 'attachment; filename="notes.pdf"');
    Tells the browser to trigger the operating system's file download / "Save As" prompt without navigating away from the current page.
Q6: How did you solve CORS (Cross-Origin Resource Sharing) issues during development?

Answer: In local development, the React Vite client runs on http://localhost:5173, while the Express server runs on http://localhost:3000. Since protocol, domain, or port differ, the browser blocks requests under the Same-Origin Policy (SOP).

We solved this by configuring the Express cors middleware with an allowed origin list (localhost:5173, localhost:3000, and irodovplusclasses.in) and enabling credentials: true to allow authenticated cookies and authorization headers across domains.

Q7: How would you scale this application from 500 students to 100,000 active students?

Answer:

  1. File Decoupling: Move PDF and image storage from MongoDB buffers to AWS S3 behind an AWS CloudFront CDN for low-latency worldwide downloads.
  2. Caching Layer: Deploy Redis to cache frequently queried resource lists and gallery images, reducing MongoDB read operations by 80%+.
  3. Database Sharding & Indexes: Add compound indexes on MongoDB (e.g. { subject: 1, classGrade: 1, createdAt: -1 }) and read replicas.
  4. Stateless Horizontal Scaling: Containerize the Node.js backend using Docker and deploy behind an Nginx / AWS ALB load balancer across multiple auto-scaling instances. Since our JWT authentication is stateless, any server instance can verify student tokens without session sticky routing.
  5. Rate Limiting: Implement express-rate-limit to protect auth endpoints against brute force attacks.
